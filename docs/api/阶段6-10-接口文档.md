> 版本：v1.9.0（阶段 6 报警与 1078、阶段 7 计价结算、阶段 8 发票、阶段 9 报表大屏、阶段 10 司机端）

## 一、阶段 6：报警中心与媒体

### 1.1 报警来源与三级规则

- 0x0200 报警位按 `AlarmType` 映射（Bit 定义未改动）；同车同类型 30 分钟内未结束报警不重复建单。
- 等级优先取 `t_alarm_rule_config`（车辆 > 车队 > 全局），否则取枚举默认等级。
- 定时任务每分钟升级未处置报警：一级 10 分钟 → 二级，二级 5 分钟 → 三级（可用 `alarm.escalate.*` 配置）。
- 处置：`ACK` 受理（0→1）、`HANDLE` 完成（→2）、`IGNORE` 忽略（→3），后两者必须填写说明。

### 1.2 REST

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/alarms` | alarm:view | 分页；参数 `alarmType,level,handleStatus,fleetId,start,end,page,size` |
| GET | `/alarms/{id}` | alarm:view | 详情 |
| POST | `/alarms/{id}/handle` | alarm:handle | `{action:"ACK|HANDLE|IGNORE",remark}` |
| GET | `/alarms/{id}/media` | media:view | 关联媒体列表 |
| POST | `/alarms/{id}/snapshot?channel=1` | media:live | 0x8801 抓拍；终端离线返回 400 |
| POST | `/alarms/{id}/live?channel=1&streamType=1` | media:live | 0x9101 请求推流，返回 MediaMTX HLS 地址 |
| POST | `/alarms/{id}/live/stop?channel=1` | media:live | 0x9102 停止 |
| GET | `/media` | media:view | 媒体库分页 |
| GET | `/media/{id}/file?download=true` | media:view | 文件预览/下载（服务端校验报警车队归属） |

报警详情示例：

```json
{"code":200,"data":{"id":"...","alarmNo":"AL20261107234440001","alarmType":"OVERSPEED",
"alarmTypeDesc":"超速报警","alarmLevel":2,"alarmLevelDesc":"二级报警","plateNo":"沪A00001",
"alarmFlagHex":"0x00000002","handleStatus":0,"handleStatusDesc":"未处置","escalateFlag":0}}
```

### 1.3 WebSocket

```
ws://host:8080/ws/v1/alarm?token=<JWT>
```

- 握手校验 `alarm:view`；
- 建连 `{"type":"ready"}`；
- 新报警/升级 `{"type":"alarm","escalated":false,"data":{...AlarmView}}`；
- 客户端可发 `ping`，服务端回 `pong`。

### 1.4 1078 / 808 下行与媒体归档

| 消息 | 方向 | 实现 |
|---|---|---|
| 0x9101 | 下行 | 实时音视频请求（通道、音视频类型、码流、推流地址、TCP/UDP 端口） |
| 0x9102 | 下行 | 停止/暂停/继续 |
| 0x8801 | 下行 | 立即拍摄（通道、分辨率等） |
| 0x8300 | 下行 | 文本信息（发票降级短链） |
| 0x8F01 | 下行 | 发票信息（订单号、发票号、PDF 地址） |
| 0x0801 | 上行 | 多媒体上传，落盘并挂最近未结束报警 |
| 0x1210 | 上行 | 报警附件信息（报警编号 + 文件列表） |
| 0x1211 | 上行 | 附件分片（文件名、偏移、数据） |
| 0x1212 | 上行 | 附件完成，登记 `t_alarm_media` |

媒体根目录 `media.storage-path`（默认 `./media`），HLS 基址 `media.hls-base`（默认 `http://127.0.0.1:8888`）。
固件厂商若对 0x1210 的报警编号长度或附件字段有差异，需在 `Jt808Bodies.AttachmentInfo` 调整偏移，原始报文应留痕。

## 二、阶段 7：计价与结算

### 2.1 计价公式

```
起步价 + Σ(里程区间 × 区间单价) + ceil(等候分钟) × 等候单价
       + 夜间加成(小计 × 夜间系数) + 燃油附加 - 优惠
```

阶梯明细来自 `t_pricing_plan_item.item_type=2`，区间左闭右开、最后一段无上限；金额四舍五入到分。

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/billing/plans` | pricing:view | 方案列表 |
| POST | `/billing/quote` | pricing:view | `{planId,mileage,waitingSeconds,night,discount}` 试算 |
| GET | `/billing/settlements` | settle:view | 结算单分页 |
| POST | `/billing/settlements/generate?start=&end=&fleetId=` | settle:generate | 按司机生成，重复自动跳过 |
| POST | `/billing/settlements/{id}/confirm` | settle:confirm | 待确认→已确认 |
| POST | `/billing/settlements/{id}/pay` | settle:pay | 已确认→已打款 |
| GET | `/billing/settlements/export?start=&end=` | settle:export | CSV（带 BOM） |

结算口径：周期内 `CALCULATED/INVOICE_*` 且 `settle_status=0` 的订单按司机汇总；
司机分成取匹配方案的 `driver_share_rate`（默认 0.8），平台费为差额；生成后订单置 `settle_status=1`。

试算示例（12km、等候 180s、无夜间）：

```json
{"code":200,"data":{"lines":[{"name":"起步价","amount":14.00},{"name":"里程费","amount":23.90},
{"name":"等候费","amount":1.50},{"name":"燃油附加","amount":1.00}],"total":40.40,"payable":40.40}}
```

## 三、阶段 8：电子发票

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/invoices` | invoice:view | 分页 `keyword,status` |
| POST | `/invoices/apply` | invoice:issue | `{orderId,buyerName,buyerEmail,buyerTaxNo}`，orderId 幂等 |
| GET | `/invoices/{id}` | invoice:view | 详情 |
| POST | `/invoices/{id}/red?reason=` | invoice:red | 仅成功发票可红冲（状态 5） |

流程：CALCULATED → 提交开票（INVOICE_PENDING）→ 开票成功（INVOICE_SUCCESS）。
下发优先 0x8F01；终端离线或失败时降级 0x8300 文本短链，并写 `t_terminal_invoice_dispatch`。

配置：

```yaml
invoice:
  mock: true                 # 本地联调；生产接诺诺网关时置 false 并实现客户号/密钥
  pdf-base: https://invoice.example.com/pdf
```

当前 `mock=true` 生成确定性发票号 `INV+订单数字` 与 PDF 地址；接入真实诺诺时替换开票调用与验签，幂等键仍为 `order_id`。

|---|---|---|---|

## 七、已知边界

1. MediaMTX 未在本机运行，0x9101 已下发、HLS 地址已生成，但端到端播放未验证；
2. 1078 只实现 9101/9102/8801/8300/8F01 与 1210/1211/1212 子集，未做对讲、录像回放列表；
3. 诺诺发票为 mock 模式，真实网关验签/凭证未接入；
4. 报警升级阈值为全局配置，未按报警类型读取 `escalate_sec`（规则等级已读取）；
5. 结算默认司机分成 0.8，平台费=差额，未做阶梯/奖惩；
6. 司机端仅实现查看与「接到乘客」，未做导航、收款、在线听单。
