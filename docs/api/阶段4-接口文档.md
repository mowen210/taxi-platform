# 阶段 4 接口文档：JT/T 808 接入底座 · 注册鉴权心跳 · 905 营运报文

> 版本：阶段 4（v1.3.0）
> 传输：TCP，默认端口 **7611**（`protocol.port` 可改；`protocol.enabled=false` 可整体关闭）
> 编码：JT/T 808-2011/2019 帧格式（本阶段只处理未加密报文），905 业务字段见第五节
> 说明：本阶段只做协议解析与下发，不含 ISU 固件、串口、摄像头 SDK

---

## 一、帧格式

```
0x7E | 消息头 + 消息体 + 校验码 | 0x7E
```

| 项 | 规则 |
|---|---|
| 帧界 | `0x7E`，接收端按此扫描拆包，支持粘包/半包 |
| 转义 | `0x7E → 0x7D 0x02`；`0x7D → 0x7D 0x01`；接收端反转义后再校验 |
| 校验码 | 消息头 + 消息体逐字节异或（1 字节） |
| 加密 | 只接受加密方式 0；其它值直接拒绝并记录日志 |
| 最大帧 | 8192 字节，超长且未收尾断开连接 |
| 空闲 | 180 秒未收到任何上行报文断开连接（`protocol.idle-seconds`） |

## 二、消息头

2013 版（12 字节）：

| 字段 | 长度 | 说明 |
|---|---|---|
| 消息 ID | 2 | 见消息表 |
| 消息体属性 | 2 | bit0-9 体长度；bit10-12 加密方式；bit13 分包；bit14 版本标识 |
| 终端手机号 | 6 | BCD，12 位数字 |
| 消息流水号 | 2 | 终端自增 |

2019 版在「消息体属性」后多 1 字节协议版本（bit14=1 时存在），平台解析与应答均按请求实际格式回写。

**终端身份以消息头手机号为准**。`0x0100` 消息体里的 7 字节终端 ID 是设备序列号，不参与身份识别。

**号码位数兼容**：808 消息头是 12 位 BCD（如 `000138000001`），档案表可能是 10 位（`0138000001`）。平台按「去掉前导 0 后的数值」匹配终端与绑定关系，两处写法都能命中。

## 三、上行消息

| 消息 ID | 名称 | 鉴权要求 | 说明 |
|---|---|---|---|
| 0x0100 | 终端注册 | 否 | 校验终端档案与车辆绑定，下发鉴权码 |
| 0x0102 | 终端鉴权 | 否 | 校验鉴权码，建立在线上会话 |
| 0x0002 | 终端心跳 | 是 | 刷新会话与在线时间 |
| 0x0200 | 位置信息汇报 | 是 | 缓存最新位置，轨迹入库在阶段 5 |
| 0x0B02 | 905 营运开始 | 是 | 落巡游单并流转至「接到乘客」 |
| 0x0B05 | 905 营运结束 | 是 | 行程结束 + 计价核算，缺失订单补建异常单 |

### 3.1 0x0100 终端注册

| 字段 | 长度 | 类型 | 说明 |
|---|---|---|---|
| 省域 ID | 2 | WORD | 如 0x001F |
| 市域 ID | 2 | WORD | 如 0x0001 |
| 制造商 | 5 | ASCII | 不足补 0x00 |
| 终端型号 | 20 | ASCII | 不足补 0x00 |
| 终端 ID | 7 | ASCII | 设备序列号，不参与身份识别 |
| 车牌颜色 | 1 | BYTE | 1 蓝 2 黄 3 黑 4 白 |
| 车牌号 | 剩余 | GBK | 与档案 `plate_no` 比对（不区分大小写） |

校验顺序：终端档案存在 → 存在生效的车辆绑定 → 绑定车辆存在 → 车牌一致（车牌为空时跳过）。
通过后生成 8 位鉴权码（去除易混淆字符），写入 Redis `terminal:auth:{terminalId}`（默认 7 天）并回写档案。

### 3.2 0x0102 终端鉴权

消息体：`1 字节长度 + 鉴权码 ASCII`（兼容纯鉴权码写法）。

校验顺序：Redis 鉴权码 → 档案 `auth_code` 兜底。成功后：

- 写会话 `terminal:session:{terminalId}` = `channelId|vehicleId`，默认 5 分钟；
- 档案 `online_status=1`、`last_online_time=now`。

### 3.3 0x0002 心跳

消息体为空。刷新会话 TTL、`online_status=1`、`last_heartbeat_time`。心跳间隔必须小于会话有效期，否则需重新鉴权。

### 3.4 0x0200 位置汇报（基础 28 字节）

| 字段 | 长度 | 说明 |
|---|---|---|
| 报警标志 | 4 | 按 808 位定义，本阶段只记录日志，不产生报警工单 |
| 状态 | 4 | bit2 纬度方向（1 北纬）、bit3 经度方向（1 东经） |
| 纬度 | 4 | 度 × 10^6 |
| 经度 | 4 | 度 × 10^6 |
| 高程 | 2 | 米 |
| 速度 | 2 | km/h |
| 方向 | 2 | 0-359 |
| 时间 | 6 | BCD `YYMMDDHHmmss` |

落点：Redis `terminal:location:{terminalId}`，值 `lng|lat|speed|direction|time|alarm`，TTL 30 分钟。报警位非 0 时写 WARN 日志。

### 3.5 0x0B02 营运开始（47 字节）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 32 | 营运 ID | ASCII，不足补 0x00；平台幂等键 |
| 32 | 6 | 上车时间 | BCD `YYMMDDHHmmss` |
| 38 | 4 | 上车纬度 | 度 × 10^6 |
| 42 | 4 | 上车经度 | 度 × 10^6 |
| 46 | 1 | 计价器状态 | 1 空车 2 重车 3 暂停 |

业务规则：

1. 以 `business_id` 幂等：已存在订单直接返回成功，不重复落单；
2. 终端必须存在生效绑定，否则拒绝；
3. 车辆已有 `DISPATCHED`/`PICKUP` 订单时拒绝（一车两单）；
4. 落单来源 `order_source=1`（巡游），并在同一事务内写 3 条流转日志：`CREATE → DISPATCH（巡游自动关联）→ PICKUP`，来源 `source=2`（终端）。

### 3.6 0x0B05 营运结束（60 字节）

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 32 | 营运 ID | ASCII |
| 32 | 6 | 下车时间 | BCD |
| 38 | 4 | 下车纬度 | 度 × 10^6 |
| 42 | 4 | 下车经度 | 度 × 10^6 |
| 46 | 4 | 计费里程 | 0.1 km |
| 50 | 2 | 等候时长 | 秒 |
| 52 | 4 | 计价金额 | 分 |
| 56 | 4 | 优惠金额 | 分 |

业务规则：

| 当前状态 | 处理 |
|---|---|
| PICKUP | `FINISH`（写里程/等候/坐标/时长）→ `CALCULATE`（写金额，应收 = 计价 − 优惠），两条日志 |
| FINISHED | 只补 `CALCULATE` |
| CREATED / DISPATCHED | 未载客却收到结束报文，转 `ABNORMAL` 并写明原因 |
| CALCULATED 及以后 | 幂等忽略，仅记录日志 |
| 订单不存在 | 补建 `ABNORMAL` 订单，`abnormal_reason=仅收到 0x0B05 营运结束报文，订单为补建异常单`，日志动作 `SUPPLEMENT` |

> **905 字段布局说明**：上表是项目与模拟器约定的字段顺序（依据需求书「0x0B02 载客 / 0x0B05 结束」的要求实现）。厂商实际报文若有偏移差异，先看 `t_taximeter_raw_YYYYMMDD.raw_hex` 留痕，再只改 `Jt808Bodies` 的偏移，不动业务层。

## 四、下行消息

### 4.1 0x8001 通用应答

| 字段 | 长度 | 说明 |
|---|---|---|
| 应答流水号 | 2 | 对应请求流水号 |
| 应答消息 ID | 2 | 对应请求消息 ID |
| 结果 | 1 | 0 成功 1 失败 2 消息有误/不支持 |

### 4.2 0x8100 注册应答

| 字段 | 长度 | 说明 |
|---|---|---|
| 应答流水号 | 2 | 对应注册请求流水号 |
| 结果 | 1 | 0 成功 2 数据库中无该车辆/终端 |
| 鉴权码 | 8 | 仅成功时携带，ASCII |

### 4.3 结果码语义

| 结果码 | 场景 |
|---|---|
| 0 | 处理成功 |
| 1 | 业务失败：未鉴权、车辆有未结束订单、优惠大于计价、车牌不一致等（失败原因写日志，不占用终端连接） |
| 2 | 消息体长度不足/字段非法/平台不支持该消息 |

平台对失败一律回 0x8001（注册回 0x8100），不主动断链，避免终端因单条脏数据反复重连。

## 五、报文落库

`0x0B02` / `0x0B05` 原始帧十六进制写入按日分表 `t_taximeter_raw_YYYYMMDD`：

- 每天首次写入时按模板表 `t_taximeter_raw_20260101` 复制结构（`CREATE TABLE IF NOT EXISTS ... LIKE`）；
- `parse_status`：1 解析成功，2 解析失败；失败原因写 `parse_error`；
- `uk_business(business_id, biz_type)` 兜底重复上报，重复直接忽略；
- 业务失败也留痕，因此「报文到了但业务拒绝」可对账。

## 六、配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `protocol.enabled` | true | 是否启动 808 服务 |
| `protocol.port` | 7611 | TCP 端口 |
| `protocol.worker-threads` | 0 | 0 表示按 CPU 自动计算 |
| `protocol.idle-seconds` | 180 | 空闲断链阈值 |
| `protocol.auth-ttl` | 7d | 鉴权码有效期 |
| `protocol.session-ttl` | 5m | 在线会话有效期（心跳刷新） |

## 七、模拟器

```bash
# Java（纯 JDK，单文件运行，无需依赖）
java simulator/Jt808Simulator.java --host 127.0.0.1 --port 7611 \
  --terminal 0138000001 --plate 沪A00001 --business BIZ-20261107-001

# Python 3（仅标准库）
python simulator/jt808_simulator.py --host 127.0.0.1 --port 7611 \
  --terminal 0138000001 --plate 沪A00001 --business BIZ-20261107-001
```

可选参数：

| 参数 | 说明 |
|---|---|
| `--mileage` / `--amount` / `--discount` / `--waiting` | 0x0B05 的里程、金额、优惠、等候秒数 |
| `--register-only` | 只注册，用于验证未备案终端（预期 result=2） |
| `--skip-auth` | 跳过鉴权直接发 0x0B02，用于验证未鉴权拒绝（预期 result=1） |

## 八、当前不支持（按阶段推进）

- 0x8103 参数下发、0x8201 位置查询、0x8300 文本下发、0x8F01 发票下发（阶段 5/8）；
- 报文加密（加密方式非 0 直接拒绝）；
- 轨迹时序入库（阶段 5 接 TDengine）；
- 集群化会话与分包重组（当前为单节点内存 + Redis 会话）。
