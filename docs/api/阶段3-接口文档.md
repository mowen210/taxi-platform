## 二、状态机（固定 10 态，禁止新增）

```
CREATED ──派单──> DISPATCHED ──接到乘客──> PICKUP ──行程结束──> FINISHED ──核算──> CALCULATED
   │                  │                                            │                  │
   └──取消──> CANCELLED └──取消──> CANCELLED（未载客）              └──转异常──> ABNORMAL ──核算──> CALCULATED
                                                                                      └──取消──> CANCELLED

CALCULATED ──提交开票──> INVOICE_PENDING ──成功──> INVOICE_SUCCESS（终态）
                                       └──失败──> INVOICE_FAIL ──重试──> INVOICE_PENDING ──超限──> ABNORMAL
```

| 动作 | 允许的当前状态 | 目标状态 |
|---|---|---|
| DISPATCH 派单 | CREATED、ABNORMAL | DISPATCHED |
| UNDISPATCH 撤回 | DISPATCHED | CREATED |
| PICKUP 接客 | DISPATCHED | PICKUP |
| FINISH 结束行程 | PICKUP | FINISHED |
| CALCULATE 核算 | FINISHED、ABNORMAL | CALCULATED |
| SUBMIT_INVOICE 提交开票 | CALCULATED、INVOICE_FAIL | INVOICE_PENDING |
| INVOICE_SUCCESS / INVOICE_FAIL | INVOICE_PENDING | INVOICE_SUCCESS / INVOICE_FAIL |
| CANCEL 取消 | CREATED、DISPATCHED、ABNORMAL | CANCELLED |
| MARK_ABNORMAL 转异常 | 任意非终态 | ABNORMAL |

强制规则：
1. 终态 `INVOICE_SUCCESS`、`CANCELLED` 不再接受任何流转；
2. **已载客（PICKUP 及之后）不允许取消**，只能转异常单人工复核；
3. 非法流转返回 400 并给出可读原因，例如
   `{"code":400,"msg":"订单当前状态「已派单」不允许行程结束：仅「接到乘客」可结束行程"}`；
4. 每次流转在同一事务内写 `t_order_status_log`，并返回 `nextActions` 供前端置灰按钮。

## 四、创建电召订单

`POST /api/v1/orders`，请求头可选 `X-Idempotency-Key`。

```json
{"passengerName":"测试乘客","passengerPhone":"13812345678",
 "startAddress":"人民广场","startLng":121.4737,"startLat":31.2304,
 "endAddress":"虹桥机场","endLng":121.3269,"endLat":31.1979,
 "pricingPlanId":null,"remark":""}
```

| 字段 | 必填 | 校验 |
|---|---|---|
| passengerName | 否 | ≤64 |
| passengerPhone | 否 | 11 位手机号；入库 AES-GCM 加密，出参脱敏 |
| startAddress / endAddress | 否 | ≤255 |
| startLng / startLat / endLng / endLat | 否 | 经度 -180~180，纬度 -90~90 |
| pricingPlanId | 否 | 逻辑外键 `t_pricing_plan.id` |

返回：`{"code":200,"data":2119078477360570370}`（订单 ID）。

**幂等**：同一 `X-Idempotency-Key` 在 10 分钟内重复提交，返回首次创建的订单 ID；首请求未完成时返回
`{"code":400,"msg":"相同请求正在处理中，请稍后重试"}`；业务失败会释放幂等键允许重试。

## 五、派单

`POST /api/v1/orders/{id}/dispatch`

```json
{"driverId":2119076340295593985,"vehicleId":1,"remark":"电召派单"}
```

前置校验（任一不满足返回 400）：

| 校验 | 失败提示 |
|---|---|
| 司机存在且在职业 | 司机不在职，不能派单：xxx |
| 车辆存在且非维修/停运 | 车辆处于维修/停运状态，不能派单：沪A00001 |
| 车辆与订单同车队 | 车辆与订单不属于同一车队 |
| 车辆有生效的终端-计价器绑定 | 车辆未绑定终端与计价器，无法派单：沪A00001 |
| 司机无进行中订单（DISPATCHED/PICKUP） | 司机还有未完成订单，不能重复派单：xxx |
| 车辆无进行中订单 | 车辆还有未完成订单，不能重复派单：沪A00001 |
| 数据权限 | 非全局账号只能派本车队车辆，否则 403 |

派单成功后订单写入 `vehicleId / driverId / fleetId / terminalId / taximeterSn / dispatchTime`，
这些字段直接来自当前生效绑定，保证后续 808/905 报文能对上车与计价器。

## 六、接客、结束、核算

**接客** `POST /orders/{id}/pickup?pickupTime=2026-11-07T22:44:15`（时间可省略，默认服务端当前时间）

**结束** `POST /orders/{id}/finish`

```json
{"finishTime":null,"mileage":8.6,"emptyMileage":1.2,"waitingDuration":180,"durationSec":1320}
```

约束：下车时间不得早于上车时间；时间统一截断到秒（MySQL DATETIME 无小数位）。

**核算** `POST /orders/{id}/calculate`

```json
{"totalAmount":32.50,"discountAmount":2.50,"pricingPlanId":null}
```

结果：`payableAmount = totalAmount - discountAmount`（优惠不得大于计价金额），同时写 `calcTime`。
阶段 3 由调度人工录入，阶段 5 起由 905 计价引擎调用同一能力。

## 七、取消与异常

`POST /orders/{id}/cancel`

```json
{"reason":"乘客临时有事"}
```

实测：CREATED / DISPATCHED / ABNORMAL 可取消；PICKUP 及之后返回
`{"code":400,"msg":"订单已载客，不能取消；请转异常订单由人工复核"}`。

`POST /orders/{id}/abnormal`

```json
{"reason":"终端失联，里程与金额缺失"}
```

## 八、查询与详情

`GET /api/v1/orders?keyword=&status=&fleetId=&driverId=&startTime=&endTime=&page=1&size=20`

- `keyword`：订单号、乘客称呼模糊匹配；
- `status`：枚举名（非法值直接 400）；
- `startTime / endTime`：ISO 时间，作用于创建时间；
- 非全局账号自动收敛本车队。

详情返回（实测）：

 "driverId":2119076340295593985,"driverName":"阶段二司机","fleetId":1,"fleetName":"演示出租汽车队",
 "terminalId":"0138000001","taximeterSn":"TXM-DEMO-0001","passengerName":"测试乘客",
 "passengerPhoneMask":"138****5678","mileage":8.60,"totalAmount":32.50,
 "discountAmount":2.50,"payableAmount":30.00,"nextActions":["SUBMIT_INVOICE","MARK_ABNORMAL"],

## 九、错误返回实测

| 场景 | code | msg |
|---|---|---|
| 未派单直接接客 | 400 | 订单当前状态「已创建」不允许接到乘客：仅「已派单」可确认接到乘客 |
| 已派单直接结束 | 400 | 订单当前状态「已派单」不允许行程结束：仅「接到乘客」可结束行程 |
| 载客后取消 | 400 | 订单已载客，不能取消；请转异常订单由人工复核 |
| 终态再派单 | 400 | 订单已处于终态「已取消」，不允许再派单 |
| 司机重复派单 | 400 | 司机还有未完成订单，不能重复派单：阶段二司机 |
| 优惠大于金额 | 400 | 优惠金额不能大于计价金额 |
| 订单不存在 | 404 | 订单不存在：id=999999 |
| 车队管理员建单 | 403 | 缺少权限：order:create |
| 无令牌 | 401 | 缺少访问令牌 |

## 十、已知限制（阶段 3 范围）

1. 808/905 未接入，接客与结束暂由调度人工触发；阶段 4 起改由 0x0B02 / 0x0B05 驱动，调用同一服务方法。
2. 费用明细表 `t_order_item` 由阶段 5 计价引擎写入，本阶段只落总额与应收。
3. 状态变更暂未广播 WebSocket（阶段 5 与实时监控一并接入）。
4. 乘客手机号未建 HMAC 摘要列，暂不支持按手机号检索订单；如需可加列，不影响状态机。
