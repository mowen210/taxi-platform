# 阶段 1 接口文档（RBAC 与认证）

- 统一前缀：`/api/v1`
- 认证方式：`Authorization: Bearer <JWT>`
- 统一返回：`{"code":200,"msg":"success","data":{},"traceId":"9f1c..."}`
- 错误码：`200` 成功、`400` 参数错误、`401` 未登录/令牌失效、`403` 无权限、`404` 不存在、`429` 限流、`500` 服务异常
- **HTTP 状态恒为 200，业务结果看响应体 `code`**（前端 axios 拦截器统一判断 `code`）
- 所有响应头回写 `X-Trace-Id`，响应体 `traceId` 与日志一致
- Long 型 ID 序列化为字符串（避免 JS 精度丢失）

## 1. 认证

### 1.1 登录

`POST /api/v1/auth/login`（免鉴权，限流 10 次/60 秒/IP）

请求：

```json
{ "username": "admin", "password": "Admin@123" }
```

响应：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 7200,
    "user": {
      "userId": "1",
      "username": "admin",
      "realName": "系统管理员",
      "phoneMask": null,
      "email": "admin@example.com",
      "fleetId": null,
      "status": 1,
      "dataScope": 1,
      "roleIds": ["1001"],
      "permissions": ["system:user:list", "system:user:add", "..."],
      "lastLoginTime": "2026-11-07 18:40:00"
    }
  },
  "traceId": "6f2a..."
}
```

失败：

| 场景 | code | msg |
|---|---|---|
| 用户名或口令错误 | 401 | 用户名或口令错误 |
| 连续失败超阈值 | 429 | 登录失败次数过多，请 15 分钟后重试 |
| 账号停用 | 403 | 账号已停用，请联系管理员 |

### 1.2 注销

`POST /api/v1/auth/logout`（需登录）

将当前令牌 `jti` 加入 Redis 黑名单，TTL 等于令牌有效期。响应 `data` 为 `null`。

### 1.3 当前用户

`GET /api/v1/auth/me`（需登录）

返回结构同登录响应中的 `user` 对象，权限码实时从库读取。

### 1.4 修改本人口令

`PUT /api/v1/auth/password`（需登录）

```json
{ "oldPassword": "Admin@123", "newPassword": "Taxi@2026" }
```

规则：新口令 8~64 位且必须同时含字母与数字；修改成功后当前令牌立即失效，需重新登录。

## 2. 用户管理（`system:user:*`）

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| GET | `/api/v1/users` | system:user:list | 分页查询 |
| GET | `/api/v1/users/{id}` | system:user:list | 详情 |
| POST | `/api/v1/users` | system:user:add | 新增 |
| PUT | `/api/v1/users/{id}` | system:user:edit | 修改（不含口令） |
| DELETE | `/api/v1/users/{id}` | system:user:delete | 软删除 |
| PUT | `/api/v1/users/{id}/password` | system:user:reset-pwd | 重置口令 |
| PUT | `/api/v1/users/{id}/roles` | system:user:assign-role | 分配角色 |

查询参数：`keyword`（登录名/姓名/完整手机号）、`fleetId`、`status`、`page`（默认 1）、`size`（默认 20，上限 100）。

数据权限：非全局（`dataScope != 1`）账号自动把 `fleetId` 收敛为本人车队，且新增/修改时禁止跨车队。

新增请求：

```json
{
  "username": "dispatcher01",
  "password": "Dispatch@2026",
  "realName": "调度一号",
  "phone": "13800001111",
  "idCard": "310101199001011234",
  "email": "d01@example.com",
  "fleetId": 1,
  "status": 1,
  "remark": "演示账号",
  "roleIds": [1003]
}
```

响应 `data` 为新增用户 ID（字符串）。

约束：

- 用户名 4~64 位，仅字母/数字/下划线/点/横线，全局唯一
- 手机号入库前 AES-256/GCM 加密，同时写 `phone_hash`（HMAC-SHA256）用于等值检索
- 身份证入库前加密，另存 `id_card_mask`
- 接口出参只返回脱敏值（`138****1111`、`310101********1234`）
- **修改时手机号/身份证必须传明文或直接省略该字段**；把列表返回的掩码值回传会命中参数校验返回 400，这是刻意设计，防止掩码覆盖密文
- 禁止删除当前登录账号与内置管理员（id=1）
- 分配角色或重置口令后，该用户权限缓存即时失效

## 3. 角色管理（`system:role:*`）

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| GET | `/api/v1/roles` | system:role:list | 分页查询 |
| GET | `/api/v1/roles/all` | system:role:list | 全部角色（下拉） |
| POST | `/api/v1/roles` | system:role:add | 新增 |
| PUT | `/api/v1/roles/{id}` | system:role:edit | 修改 |
| DELETE | `/api/v1/roles/{id}` | system:role:delete | 删除 |
| GET | `/api/v1/roles/{id}/menus` | system:role:list | 已分配菜单 ID |
| PUT | `/api/v1/roles/{id}/menus` | system:role:assign-menu | 分配菜单 |

请求示例：

```json
{ "roleCode": "FLEET_ADMIN", "roleName": "车队管理员", "dataScope": 2, "remark": "仅本车队" }
```

约束：

- `dataScope`：1 全部 / 2 本车队 / 3 本人
- 内置 `SUPER_ADMIN` 角色编码不可改、不可删
- 角色下仍有用户时拒绝删除，提示用户数量
- 菜单分配后，该角色所有用户权限缓存即时失效

## 4. 菜单管理（`system:menu:*`）

| 方法 | 路径 | 权限码 | 说明 |
|---|---|---|---|
| GET | `/api/v1/menus/tree` | system:menu:list | 全量菜单树 |
| GET | `/api/v1/menus/mine` | 仅需登录 | 当前用户菜单树（前端动态路由） |
| POST | `/api/v1/menus` | system:menu:add | 新增 |
| PUT | `/api/v1/menus/{id}` | system:menu:edit | 修改 |
| DELETE | `/api/v1/menus/{id}` | system:menu:delete | 删除 |

菜单节点结构：

```json
{
  "id": "101",
  "parentId": "1",
  "menuType": 2,
  "menuName": "用户管理",
  "path": "/system/user",
  "component": "system/user/index",
  "permCode": "system:user:list",
  "icon": "User",
  "sortNo": 1,
  "visible": 1,
  "children": []
}
```

约束：权限码唯一且格式 `a:b:c`；按钮节点不能作为上级；存在子节点时拒绝删除。

## 5. 操作日志（`system:log:list`）

`GET /api/v1/logs?keyword=&userId=&from=2026-11-01 00:00:00&to=2026-11-07 23:59:59&page=1&size=20`

返回字段含 `traceId`、`userId`、`userName`、`module`、`action`、`method`、`requestUri`、`requestParam`、`result`、`errorMsg`、`ip`、`costMs`、`opTime`。
