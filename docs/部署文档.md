# 出租汽车运营监管平台 · 部署文档

> 适用版本：阶段 1~10（v1.9.0）
> 技术栈：Spring Boot 3 + MyBatis-Plus + Netty、MySQL 8、Redis 7、TDengine 3（可选）、Nginx、MediaMTX（可选）
> 默认端口：REST `8080`、JT/T 808 接入 `7611`、MySQL `3306`、Redis `6379`、TDengine REST `6041`、MediaMTX RTSP `8554` / HLS `8888`、Nginx `80`

---

## 一、部署拓扑

```
终端(计价器+ISU) --808/905--> :7611  ┐
浏览器 --HTTP/WebSocket------> :8080  ├─ taxi-platform.jar ── MySQL 8
                                   │                     └─ Redis 7
                                   ├─ TDengine（轨迹，可选；默认 MySQL 兜底）
                                   ├─ MediaMTX（1078 推流/HLS，可选）
                                   └─ Nginx（统一 80 入口，可选）
```

最小可运行依赖只有 **MySQL 8 + Redis 7 + JDK 17**。TDengine、MediaMTX、Nginx 均为可选增强。

## 二、前置条件

| 项目 | 要求 |
|---|---|
| JDK | 17（`java -version`） |
| Maven | 3.9+ |
| Docker | 24+，Compose v2（容器化部署时） |
| 内存 | 建议 4 GB 起；TDengine/MediaMTX 同机建议 8 GB |
| 端口 | 8080、7611 必开；3306、6379 仅内网；80/443 按需 |
| 时区 | 统一 `Asia/Shanghai`，MySQL 会话 `+08:00` |

## 四、配置（唯一配置源）

所有运行参数集中在 **`config/taxi.env`**。Spring Boot 启动时由
`DotenvEnvironmentPostProcessor` 自动加载；Docker Compose 通过 `env_file`
注入；systemd 通过 `EnvironmentFile` 读取。代码中只保留 `${KEY:默认值}` 引用，
不再分散配置。

```bash
cd taxi-platform
cp config/taxi.env.example config/taxi.env
```

必须修改的项：

```ini
DB_HOST=mysql                    # Docker 用 mysql；裸机用 127.0.0.1/实际地址
DB_PASSWORD=<强口令>
JWT_SECRET=<至少32字节随机串>
HMAC_SECRET=<随机串>
AES_KEY=<32字节随机数的Base64>
```

生成示例：

```bash
openssl rand -base64 48          # JWT_SECRET / HMAC_SECRET
openssl rand -base64 32          # AES_KEY（必须是 32 字节的 Base64）
```

主要可配置项（完整清单见模板）：

```ini
SERVER_PORT=8080                 # REST 端口
PROTOCOL_PORT=7611               # JT/T 808 端口
TRACK_PROVIDER=mysql             # 无 TDengine 时保持 mysql；生产可切 tdengine
TDENGINE_URL=http://tdengine:6041
MEDIA_STORAGE_PATH=./media       # 容器内工作目录 /app，即 /app/media
MEDIA_HLS_BASE=http://127.0.0.1:8888
MEDIA_PUSH_IP=127.0.0.1          # 下发给终端的推流地址（终端能访问到的 IP）
MEDIA_PUSH_PORT=8554
INVOICE_MOCK=true                # 未接诺诺前保持 true
ALARM_LEVEL1_SECONDS=600         # 一级报警升级阈值
ALARM_LEVEL2_SECONDS=300         # 二级报警升级阈值
BILLING_DEFAULT_DRIVER_SHARE=0.8000
CORS_ALLOWED_ORIGINS=http://localhost:*,http://127.0.0.1:*
```

加载优先级：

1. `-D` 系统属性 / 操作系统环境变量（最高）
2. `config/taxi.env`
3. `application.yml` 中的默认值（最低）

自定义路径：`TAXI_CONFIG_FILE=/opt/taxi/config/taxi.env` 或
`java -Dtaxi.config.file=/opt/taxi/config/taxi.env -jar ...`。

> `config/taxi.env` 含密钥，已在 `.gitignore` 中排除，禁止提交；模板
> `config/taxi.env.example` 可以提交，但其中的示例密钥必须替换。

## 五、Docker Compose 部署（推荐）

### 5.1 构建并启动

```bash
mvn -B -DskipTests package
docker compose -f deploy/docker-compose.yml --env-file config/taxi.env up -d
```

`--env-file` 负责 Compose 变量替换（端口、数据库口令）；`env_file` 负责把同一份
配置注入 app 容器，二者都指向 `config/taxi.env`。

首次启动时 MySQL 会按文件名顺序执行 `deploy/mysql/init/01~10*.sql`。

### 5.2 可选 TDengine

Compose 中 TDengine 使用 `track` profile，默认不启动：

```bash
# 启动 TDengine
docker compose -f deploy/docker-compose.yml --env-file config/taxi.env --profile track up -d tdengine

# 初始化轨迹库（镜像不会自动执行挂载脚本时手动执行）
docker compose exec tdengine taos -f /docker-entrypoint-initdb.d/01_track.sql
```

然后把 `config/taxi.env` 改为 `TRACK_PROVIDER=tdengine` 并重启 app：

```bash
docker compose -f deploy/docker-compose.yml --env-file config/taxi.env up -d app
```

没有 TDengine 时务必保持 `TRACK_PROVIDER=mysql`，轨迹写入 `t_track` 兜底表。

### 5.3 验证

```bash
curl -fsS http://127.0.0.1:8080/api/v1/health
docker compose -f deploy/docker-compose.yml ps
docker compose -f deploy/docker-compose.yml logs -f app
```

浏览器打开：

- 管理登录：`http://<host>/login`
- 管理首页：`http://<host>/admin`
- 基础信息设置：`http://<host>/base`（车队、司机、车辆、终端绑定、发票）
- 监控：`http://<host>/monitor.html`
- 报警：`http://<host>/alarm.html`
- 大屏：`http://<host>/dashboard.html`
- 司机端：`http://<host>/driver.html`

Nginx 已将 `/` 重定向到 `/login`，并代理登录页、管理首页、基础信息页、监控/报警/大屏/司机端页面、`/api/`、`/ws/`。

### 5.4 已有数据库的升级

Docker 的初始化脚本只在数据卷首次创建时执行。已有库按顺序手工补：

```bash
for f in deploy/mysql/init/0[3-9]*.sql deploy/mysql/init/10*.sql; do
  docker compose exec -T mysql mysql -uroot -p"$DB_PASSWORD" taxi_platform < "$f"
done
```

脚本均为幂等写法（`CREATE TABLE IF NOT EXISTS` / `ON DUPLICATE KEY UPDATE`），可重复执行。

## 六、裸机部署

### 6.1 MySQL

```sql
CREATE DATABASE IF NOT EXISTS taxi_platform
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'taxi'@'%' IDENTIFIED BY '<强口令>';
GRANT ALL PRIVILEGES ON taxi_platform.* TO 'taxi'@'%';
FLUSH PRIVILEGES;
```

```bash
mysql -utaxi -p taxi_platform < deploy/mysql/init/01_schema.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/02_seed.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/03_stage2_menu.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/04_stage3_order.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/05_stage5_monitor.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/06_stage6_alarm.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/07_stage7_billing.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/08_stage8_invoice.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/09_stage9_stats.sql
mysql -utaxi -p taxi_platform < deploy/mysql/init/10_stage10_driver.sql
```

`01_schema.sql` 已包含建库语句；若库已存在可忽略重复建库错误。

### 6.2 Redis

```bash
redis-server --appendonly yes --maxmemory-policy noeviction
```

生产建议启用密码并通过防火墙限制来源。

### 6.3 启动应用

所有参数已在 `config/taxi.env` 中，应用启动时自动加载；只需保证工作目录包含
`config/taxi.env`（或设置 `TAXI_CONFIG_FILE`）：

```bash
cd /opt/taxi-platform
cp config/taxi.env.example config/taxi.env   # 首次
# 编辑 config/taxi.env：DB_HOST、DB_PASSWORD、密钥、媒体目录等

java -XX:MaxRAMPercentage=70 -Duser.timezone=Asia/Shanghai \
  -jar taxi-api/target/taxi-platform.jar
```

如果配置文件不在默认位置：

```bash
TAXI_CONFIG_FILE=/opt/taxi/config/taxi.env \
  java -Duser.timezone=Asia/Shanghai -jar taxi-api/target/taxi-platform.jar
```

### 6.4 systemd（示例）

`/etc/systemd/system/taxi-platform.service`：

```ini
[Unit]
Description=Taxi Platform
After=network.target mysql.service redis-server.service

[Service]
Type=simple
User=taxi
WorkingDirectory=/opt/taxi-platform
EnvironmentFile=/opt/taxi-platform/config/taxi.env
ExecStart=/usr/bin/java -XX:MaxRAMPercentage=70 -Duser.timezone=Asia/Shanghai \
  -jar /opt/taxi-platform/taxi-api/target/taxi-platform.jar
Restart=always
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload
systemctl enable --now taxi-platform
journalctl -u taxi-platform -f
```

### 6.5 Nginx

可直接使用 `deploy/nginx/nginx.conf`，将其放入 `/etc/nginx/conf.d/taxi.conf`，把 `app:8080` 改为 `127.0.0.1:8080`。配置已包含：

- `/api/` 反向代理；
- `/ws/` WebSocket 升级与 1 小时读超时；
- `/login`、`/admin`、`/base` 反代到后端；
- `/login.html|admin.html|base.html|monitor.html|alarm.html|dashboard.html|driver.html` 及 `monitor.css/js`、`base.css/js` 代理；
- `/` 302 到 `/login`。

生产启用 HTTPS 时，在 443 server 中复用上述 location 并配置证书。

## 七、MediaMTX（1078 实时预览）

平台不内嵌流媒体服务，需单独部署 MediaMTX：

```yaml
# mediamtx.yml
rtsp: yes
rtspAddress: :8554
hls: yes
hlsAddress: :8888
hlsAllowOrigins: ["*"]
paths:
  all_others:
```

```bash
docker run -d --name mediamtx -p 8554:8554 -p 8888:8888 \
  -v $PWD/mediamtx.yml:/mediamtx.yml bluenviron/mediamtx:latest
```

应用侧：

```ini
MEDIA_PUSH_IP=<终端可访问的服务器IP>
MEDIA_PUSH_PORT=8554
MEDIA_HLS_BASE=http://<浏览器可访问的服务器IP>:8888
```

报警页「实时预览」会下发 0x9101，终端向 `rtsp://MEDIA_PUSH_IP:8554/<终端号>/<通道>` 推流，
浏览器播放 `MEDIA_HLS_BASE/<终端号>/<通道>/index.m3u8`。防火墙需放行 8554/8888。

> 本机交付验证时未启动 MediaMTX，HLS 地址生成与 0x9101 下发已验证，实际播放需按上述方式联调。

## 八、初始化账号与安全

| 账号 | 初始口令 | 角色 |
|---|---|---|
| `admin` | `Admin@123` | 超级管理员 |
| `fleetadmin` | `Fleet@2026` | 车队管理员 |
| `driver01` | `Admin@123` | 司机（绑定司机 1） |

上线前必须：

1. 修改全部初始口令；
2. 替换 JWT/AES/HMAC 密钥，`AES_KEY` 变更后旧密文无法解密，需评估迁移；
3. 关闭或限制 Swagger：`SPRINGDOC_ENABLED=false`；
4. 防火墙只暴露 80/443、7611；3306/6379/6041 仅内网；
5. 启用 Nginx HTTPS，并限制 8080 直连；
6. 定期备份 MySQL 与媒体目录，妥善保管 `config/taxi.env`。

## 九、终端接入与联调

1. 在「车辆管理 → 终端绑定」登记终端号并绑定车辆；
2. 终端配置平台地址 `tcp://<host>:7611`；
3. 终端先 0x0100 注册，平台下发 8 位鉴权码（Redis 7 天）；
4. 0x0102 鉴权后发 0x0002 心跳与 0x0200 定位；
5. 用模拟器验证：

```bash
java simulator/Jt808Simulator.java --host 127.0.0.1 --port 7611 \
  --terminal 0138000001 --plate 沪A00001 --business BIZ-DEMO-001 \
  --locations 10 --alarm 1

py -3 simulator/jt808_simulator.py --host 127.0.0.1 --port 7611 \
  --terminal 0138000001 --plate 沪A00001 --business BIZ-DEMO-002 --alarm 2
```

6. 观察 `/monitor.html` 轨迹、`/alarm.html` 报警与 WebSocket 推送。

## 十一、备份、升级与回滚

### 备份

```bash
mysqldump -utaxi -p --single-transaction --routines taxi_platform \
  | gzip > taxi_$(date +%F_%H%M).sql.gz
tar czf media_$(date +%F).tar.gz /data/taxi/media
redis-cli BGSAVE
```

建议每日备份数据库、每周备份媒体；媒体保留期按 `t_alarm_media.retain_until` 执行。

### 升级

```bash
systemctl stop taxi-platform
cp taxi-api/target/taxi-platform.jar /opt/taxi-platform/backup/taxi-platform-$(date +%F).jar
mvn -B -DskipTests package
# 执行新增 deploy/mysql/init/xx.sql
cp taxi-api/target/taxi-platform.jar /opt/taxi-platform/taxi-api/target/
systemctl start taxi-platform
curl -fsS http://127.0.0.1:8080/api/v1/health
```

### 回滚

停服务 → 恢复上一版 jar → 如涉及表结构，用备份库恢复 → 启动并验证健康检查。

## 十二、常见问题

| 现象 | 排查 |
|---|---|
| 启动报数据库连接失败 | `config/taxi.env` 的 `DB_HOST/DB_PORT`；MySQL 是否允许远程；`sessionVariables` 时区参数是否被代理改写 |
| 登录失败 | 看返回体 `code=401/403`；令牌是否过期；用户角色是否授予对应菜单；`TokenStore` Redis 是否可写 |
| 静态页打不开 | `JwtAuthFilter` 应对 `.html`、`/monitor*`、`/ws/` 放行；Nginx 是否代理到后端 |
| WebSocket 握手失败 | 必须带 `?token=`；Nginx `/ws/` 是否设置 `Upgrade/Connection`；权限码是否存在 |
| 终端一直离线 | 7611 是否放行；终端注册/鉴权码；Redis `terminal:session`；心跳 5 分钟内是否刷新 |
| 轨迹为空 | `TRACK_PROVIDER` 与数据库；绑定关系 `bind_status=1`；0x0200 是否鉴权后上报 |
| 报警不生成 | 0x0200 报警位是否为 0；同车同类型 30 分钟去重；`t_alarm_rule_config` 是否禁用 |
| 媒体下载 404 | `MEDIA_STORAGE_PATH` 是否挂载持久卷；文件是否已归档 |
| 发票一直待下发 | 终端离线；`INVOICE_MOCK`；`t_terminal_invoice_dispatch` 状态；0x8F01/0x8300 是否被终端支持 |
| TDengine 写入失败 | 6041 是否可达；`taosAdapter` 是否启动；`TRACK_PROVIDER` 是否误设为 tdengine |
| 大屏无数据 | 当天是否有订单/报警；统计按 `finish_time/create_time` 聚合 |
| 容器 healthcheck unhealthy | 确认镜像内 bash 可用；或改为 `curl` 并安装 curl；以 `/api/v1/health` 实测为准 |

## 十三、当前版本已知限制

1. TDengine 轨迹实现未在本机端到端验证，默认使用 MySQL 兜底表。
2. MediaMTX 未随包部署，1078 实时播放需按第七章单独联调。
3. 诺诺发票默认 mock，真实网关凭证与验签未接入。
4. 报警规则编辑页面/接口未实现，规则等级读取已生效。
5. 司机端仅提供本人行程与「接到乘客」，未含听单、导航、收款。
6. 结算按方案分成比例计算，未含阶梯服务费、奖惩和调整项。
