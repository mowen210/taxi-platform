## 三、本轮发现并修复的缺陷（均由真实运行暴露）

### 1. JDBC 会话时区与数据库服务器不一致

现象：`SELECT NOW()` 返回 `14:44`（UTC），而应用写入的订单时间是 `22:44`（+08），同一张表两套时间口径。

根因：MySQL 服务器 `time_zone=SYSTEM`（UTC），JDBC URL 只声明了 `serverTimezone=Asia/Shanghai`，该参数描述「服务器时区」但不改变会话，导致 `CURRENT_TIMESTAMP` 默认值与 Java 写入值相差 8 小时。

修复：连接串增加
`sessionVariables=time_zone='%2B08:00'`，让每个连接会话固定 +08:00。
验证：新连接 `SESSION_NOW=2026-11-07 22:45:24`，`@@session.time_zone=+08:00`；订单 `create_time` 与首条状态日志 `create_time` 完全一致（均为 22:44:14）。

### 2. 订单时间纳秒比较被 MySQL 秒级四舍五入放大

现象：刚接客后立即结束行程，返回「下车时间不能早于上车时间」。

根因：`LocalDateTime.now()` 带纳秒，MySQL `DATETIME`（0 位小数）四舍五入，`22:44:15.6` 落库变 `22:44:16`；随后结束时间 `22:44:15.9` 比库里的 `22:44:16` 小，校验误判。

修复：订单时间统一 `withNano(0)`（派单、接客、结束、核算），比较口径与存储精度一致。复测 TC3-09 通过。
