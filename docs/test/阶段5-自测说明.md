## 四、本轮发现的问题与处理

| # | 问题 | 处理 |
|---|---|---|
| 1 | 在线判定口径：808 会话键用消息头 12 位号码（去零后 `138000001`），档案绑定是 `0138000001`，直接 `hasKey` 会全部判离线 | `TokenStore.hasSession` 先查原值、再查去前导 0 值；实测在线车辆 `onlineStatus=1`，离线车辆为 0 |
| 2 | 本机没有 TDengine，也不允许装 Docker | 轨迹仓储做双实现，默认 MySQL 兜底；TDengine 实现按 taosAdapter REST 编写并用 5 个 SQL 单测覆盖，文档明确标注未端到端 |
| 3 | 模拟器只能发一个定位点，无法验证回放曲线 | 两个模拟器都加 `--locations N`，按 0.0012 经度 / 0.0008 纬度步进连报 |
| 4 | 车队管理员查菜单时用 `/menus/tree` 返回空 | 该接口是管理端全量树；普通账号应用 `/menus/mine`，已按正确接口复测 |

第 1 条属于只有接真终端才会暴露的口径问题（和阶段 4 的 12/10 位号码问题同源），已在实现期修掉并纳入实测。

## 五、已知限制

1. **TDengine 未端到端验证**：SQL 构造、REST 调用与响应解析已实现，待时序库就绪后按 `TRACK_PROVIDER=tdengine` 切换验证。
2. **WebSocket 单节点**：会话在内存，集群需 Redis Pub/Sub；广播在协议线程同步执行，终端规模大时需独立线程池。
3. **轨迹与订单未关联**：`order_no` 暂空，阶段 7 结算时按车辆+时间窗补齐。
4. **报警未成单**：0x0200 的报警位只写日志/透传，三级处置在阶段 6。
5. **监控列表上限 500 台**，且逐车查绑定，车辆规模大时需批量查询与分页。
6. **高德地图未验证渲染**：页面支持 `?amapKey=`，本机无 Key、未做地图截图验证；Canvas 模式已可用。
7. 轨迹查询默认最近 2 小时、最多 5000 点，长时段回放需分段拉取。
