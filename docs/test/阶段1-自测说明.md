# 阶段 1 自测说明

> 交付内容：脚手架 + 数据库初始化 + RBAC + 统一返回 + 全局异常 + 参数校验 + JWT + 日志框架
> 已验证：`mvn package` 编译通过（6 个模块）；`mvn test` 单元测试 18 个用例全部通过

## 一、环境准备

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 17+ | 本次验证使用 PyCharm 自带 JBR 25（`--release 17` 编译） |
| Maven | 3.9+ | 本次使用本地 3.9.9 |
| MySQL | 8.0 | 字符集 utf8mb4 |
| Redis | 7.x | 无密码亦可 |

本地起库（无 Docker 时）：

```bash
mysql -uroot -p < deploy/mysql/init/01_schema.sql
mysql -uroot -p < deploy/mysql/init/02_seed.sql
```

有 Docker 时：

```bash
cp .env.example .env
docker compose -f deploy/docker-compose.yml --env-file .env up -d mysql redis
```

## 四、功能自测用例

### TC-01 健康检查（免鉴权）

```bash
curl -s http://127.0.0.1:8080/api/v1/health
```

期望：`code=200`，`data.status=UP`，响应头含 `X-Trace-Id`。

### TC-02 登录成功

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Admin@123"}'
```

期望：`code=200`，返回 `token`、`expiresIn=7200`、`permissions` 含 `system:user:list` 等 16 个权限码。

### TC-03 登录失败与锁定

连续 5 次错误口令：

```bash
for i in 1 2 3 4 5 6; do
  curl -s -X POST http://127.0.0.1:8080/api/v1/auth/login \
    -H "Content-Type: application/json" \
    -d '{"username":"admin","password":"wrong-pass"}'; echo;
done
```

期望：前 5 次 `code=401`；第 6 次 `code=429`，提示锁定分钟数。等待锁定期结束或清理 Redis 键 `login:fail:admin` 后恢复。

### TC-04 未带令牌访问

```bash
curl -s http://127.0.0.1:8080/api/v1/users
```

期望：`code=401`，`msg=缺少访问令牌`，HTTP 状态 200。

### TC-05 参数校验

```bash
TOKEN=<上一步 token>
curl -s -X POST http://127.0.0.1:8080/api/v1/users \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"username":"ab","password":"123"}'
```

期望：`code=400`，`msg` 同时提示用户名长度与口令长度问题（多条用「；」拼接）。

### TC-06 新增用户（加密与脱敏）

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/users \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"username":"dispatcher01","password":"Dispatch@2026","realName":"调度一号","phone":"13800001111","idCard":"310101199001011234","fleetId":1,"status":1,"roleIds":[1003]}'
```

验证：

```sql
-- 密文入库、摘要存在
SELECT username, phone, phone_hash, id_card, id_card_mask FROM t_user WHERE username='dispatcher01';
SELECT * FROM t_user_role WHERE user_id=(SELECT id FROM t_user WHERE username='dispatcher01');
```

期望：`phone`、`id_card` 为 Base64 密文，`phone_hash` 为 64 位十六进制，`id_card_mask` 为 `310101********1234`。

再用 `GET /api/v1/users?keyword=13800001111` 检索，期望能命中（走 `phone_hash`），且返回的 `phoneMask` 为 `138****1111`。

### TC-07 权限校验（越权 403）

用 `dispatcher01`（仅 4 个业务菜单目录、无 `system:user:list`）登录后访问用户列表：

```bash
curl -s http://127.0.0.1:8080/api/v1/users -H "Authorization: Bearer $DISPATCHER_TOKEN"
```

期望：`code=403`，`msg=缺少权限：system:user:list`。

### TC-08 菜单树与动态路由

```bash
curl -s http://127.0.0.1:8080/api/v1/menus/mine -H "Authorization: Bearer $TOKEN"
```

期望：返回「系统管理 → 用户/角色/菜单/日志」树，子节点按 `sortNo` 升序。

### TC-09 角色分配菜单后权限即时生效

1. `PUT /api/v1/roles/1003/menus` 把 `101`（用户管理）加给调度员角色；
2. 用 `dispatcher01` 原令牌再访问 `/api/v1/users`。

期望：无需重新登录即可通过（权限缓存已被清理，下一次请求重建）。

### TC-10 软删除与审计字段

```bash
curl -s -X DELETE http://127.0.0.1:8080/api/v1/users/<id> -H "Authorization: Bearer $TOKEN"
```

```sql
SELECT id, username, deleted, create_time, update_time, create_by, update_by FROM t_user WHERE id=<id>;
```

期望：`deleted=1`，`update_by` 为操作人 ID，记录仍在库中。

### TC-11 操作日志留痕

```sql
SELECT trace_id, user_name, module, action, result, cost_ms, op_time FROM t_operation_log ORDER BY op_time DESC LIMIT 5;
```

期望：新增用户、分配角色、修改口令等动作有记录；`trace_id` 与响应体 `traceId` 一致。

### TC-12 令牌注销

```bash
curl -s -X POST http://127.0.0.1:8080/api/v1/auth/logout -H "Authorization: Bearer $TOKEN"
curl -s http://127.0.0.1:8080/api/v1/auth/me -H "Authorization: Bearer $TOKEN"
```

期望：第二次返回 `code=401`，`msg=令牌已注销，请重新登录`。

### TC-13 限流

60 秒内对 `/api/v1/auth/login` 发起超过 10 次请求。

期望：第 11 次起返回 `code=429`，`msg=请求过于频繁，请 60 秒后重试`。

### TC-14 未知接口

```bash
curl -s http://127.0.0.1:8080/api/v1/not-exists -H "Authorization: Bearer $TOKEN"
```

期望：`code=404`，提示接口不存在。
