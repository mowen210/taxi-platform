## 三、本轮发现并修复的缺陷

**JWT 未携带 `realName` 声明**：`JwtTokenProvider` 只写了 `uid / fleetId / scope`，而 `JwtAuthFilter` 按 `realName` 读取，导致绑定记录的 `operator_name` 为空。
修复：签发时增加 `.claim("realName", user.realName())`。重建重启后复测，绑定返回 `operatorName=系统管理员`，库内 `HEX(operator_name)=E7B3BBE7BB9FE7AEA1E79086E59198`（长度 5），确认写入正确。

## 五、已知限制

1. 终端表无车队字段：非全局账号的终端分页 `total` 为库内总数，列表按绑定车辆所属车队过滤，可能 `list < total`；阶段 4 补 `fleet_id` 冗余后转为库内过滤。
2. 短信为日志实现（`sms.provider=log`），`smsSent` 表示「已提交通道」，不含运营商回执。
3. 预警扫描按天去重，同一天内重复触发只保留首轮通知；阈值为全局参数 `cert.warn.days`，暂未按车队差异化。
4. 车辆、司机为软删除，历史绑定/通知仍指向原 ID，属设计预期。
